Interactive cells can return multiple typed output artifacts. Plain `print` and `println!` still work, and richer artifacts render with shared UI components.

## Output Types

Oxiquill renders these output kinds:

- Text from stdout, stderr, or display output.
- JSON values with structured formatting.
- Tables with sortable columns.
- Charts rendered with ECharts.
- Images from SVG, PNG, or JPEG data.
- Sandboxed HTML in an iframe.

Every artifact may have optional string `id`, `title`, and `caption` fields. Values received from workers are untrusted: Oxiquill validates discriminators, fields, plain-record structure, array shapes, finite numbers, row widths, MIME/base64 data, and nested values before a renderer receives them. One rejected or failing artifact shows a local diagnostic without removing valid siblings.

## Artifact Schema

| Kind    | Required fields                                                | Optional behavior                                                                                   |
| ------- | -------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `text`  | `stream: "stdout" \| "stderr" \| "display"`, `content: string` | `truncated` indicates bounded content.                                                              |
| `json`  | `value`                                                        | Cycle-aware formatting represents BigInt explicitly; `truncated` indicates bounded serialized data. |
| `table` | `columns`, rectangular `rows`                                  | `rowCount` records the original size; `truncated` marks a preview.                                  |
| `chart` | Valid `spec` described below                                   | Oversize/invalid charts become a local artifact error.                                              |
| `image` | `mime: image/png \| image/jpeg \| image/svg+xml`, valid data   | `alt` supplies the image alternative.                                                               |
| `html`  | `html: string`, `sandboxed: true`                              | Rendered with an empty sandbox, no referrer, and the restrictive CSP described below.               |

Table columns contain `key`, `label`, and optional `type`: `string`, `number`, `integer`, `boolean`, `date`, `datetime`, `null`, or `unknown`. Every row must have exactly the declared column count.

## Chart Schema

All chart specs accept optional `title`, `xLabel`, `yLabel`, `xType`, `yType`, `legend`, `tooltip`, and `dataZoom`. Axis types are `value`, `category`, `time`, and `log`. Unspecified axes default to `value`, except the category x axis intrinsic to bar charts. A heatmap always has category axes on both dimensions: its `xType` and `yType` may be omitted or set to `category`, while `value`, `time`, and `log` are rejected.

- `value` coordinates are finite numbers, and `log` coordinates are finite numbers greater than zero.
- `time` coordinates are finite epoch milliseconds or ISO-8601 strings in `YYYY-MM-DDTHH:mm:ss[.sss]Z` or `YYYY-MM-DDTHH:mm:ss[.sss]±HH:mm` form. Calendar fields and the explicit time zone must be valid.
- `category` coordinates are strings or finite numbers. For a heatmap axis with an explicit `xCategories` or `yCategories` array, each coordinate must be an exact listed string or a safe, in-range zero-based integer index. An index resolves to the category name at that position; it is never converted into a new numeric-looking category name.
- For a heatmap axis without an explicit categories array, finite numbers and strings are normalized with `String(coordinate)`. Categories are inferred in first-appearance order, so values with the same normalized label, such as `1` and `"1"`, share one category. X and Y are normalized independently when only one axis declares categories.

- `line`, `scatter`, and `area`: `series[]`, each with optional `name` and `[x, y]` points.
- `bar`: string `categories[]` plus series of numeric-or-null `values[]` with matching length.
- `histogram`: `bins[]` as finite `[lower, upper, count]` tuples, where `lower < upper` and count is non-negative.
- `heatmap`: optional string `xCategories`/`yCategories` arrays and finite `[x, y, value]` cells on two category axes.

Empty charts and equal point domains are valid. Heatmaps report X- and Y-category counts plus the heat-value range; their color scale uses the actual heat values, with a `0–1` fallback only for an empty dataset. Charts expose a textual title/caption and bounded accessible summary or equivalent table. The implementation canvas is hidden from accessibility APIs when that equivalent is present.

Charts update their existing ECharts instance when `html[data-theme]` changes, preserving zoom, legend selections, and heatmap color-range selections and expose a retry action after a transient renderer load failure.

### Axis ranges

Use finite `xMin/xMax/yMin/yMax` bounds, with min smaller than max. Time bounds are epoch milliseconds; log bounds must be positive. Category axes do not accept numeric bounds. `xIncludeZero/yIncludeZero` are available only for value axes. Fixed bounds take precedence, but value-axis bars, histograms, and areas must include zero and cannot disable that baseline.

Data updates preserve zoom. Changing or removing authored bounds or zero inclusion resets zoom to the full domain, while retaining legend selection. Omitted bounds return to automatic scaling.

Rust line, scatter, bar, and histogram macros accept `options = &serde_json::json!({...})` after their data arguments. Options accept the public chart settings, including labels and nested style; they cannot replace the kind or data. Existing positional style arguments remain supported. See the [logistic map](../../samples/logistic-map/) for a fixed 0–1 range.

### Histogram intervals

Histograms use a numeric x axis: each rectangle spans its exact `[lower, upper)` interval, including negative boundaries, unequal widths, and gaps. Overlapping bins are rejected; non-overlapping bins need not be sorted.

The default `mode: 'count'` uses count as height. With `mode: 'density'`, height is `count / (upper - lower)` so area represents count, not normalized probability. The y label, tooltip, and summary identify the mode. A value y axis starts at zero; a log y axis uses its positive visible lower boundary and requires positive heights, so its rectangle areas are not counts.

**Migration:** explicit histogram `xType: 'category'` remains accepted but is normalized to `value`. Prefer omitting it or specifying `value`. Bin counts and boundaries are never rounded in the data.

```rust
//| id: interval-histogram
//| title: Unequal-width histogram
let bins = [[-1.0, -0.5, 2.0], [0.0, 2.0, 4.0]];
emit_histogram!(&bins, options = &serde_json::json!({
    "mode": "density", "xLabel": "Measurement", "yLabel": "Frequency"
}));
```

### Display Defaults

Bar, histogram, and area charts include zero on a value y axis; line and scatter charts fit the data. Negative amounts also use zero as their baseline. A logarithmic y axis uses the lower axis boundary, so bar lengths and filled areas cannot be compared as amounts. **Migration:** bar and histogram `yType: 'time'` is now rejected; use a value axis for amounts or a line/scatter chart for timestamps.

Numeric notation is selected per axis from the data range and remains stable while zooming. Four-digit years have no grouping separators. Large and tiny ranges use scientific notation; a narrow range around a large offset retains ordinary notation. Ticks retain enough digits to distinguish values. Tooltips, color scales, and summaries use six significant digits; JSON and table CSV retain original values. Negative zero displays as `0`.

For a numeric range spanning zero, data values whose absolute magnitude is at most `Number.EPSILON` times the largest absolute value display as `0`. This removes roundoff such as `sin(π)` in a −1 to 1 range; axis ticks and logarithmic coordinates retain small values. Time ticks adapt to the zoomed interval, retain milliseconds where needed, and show dates even when overlap handling hides a calendar boundary.

**Migration:** time-axis ticks, tooltips, and summaries now use UTC rather than the reader's local timezone. Inputs still require epoch milliseconds or ISO-8601 strings with an explicit timezone.

Titles appear once above the plot. When artifact and spec titles differ, the spec title becomes a subtitle. HTML legends use keyboard-operable series buttons, with 25 series per page. Unnamed series receive default names. Long axis and category labels are shortened; summaries retain axis names and tooltips retain category and series names. Category labels rotate before thinning. Split charts with many long category names; use `orientation: "horizontal"` for long category names.

The fixed eight-color palette is shared across light and dark themes. On default backgrounds, adjacent colors (including the wrap to the first color) meet OKLab distance 15 in normal vision and 8 in protanopia, deuteranopia, and tritanopia simulations; each color meets 3:1 background contrast. This does not guarantee every pair of series is distinguishable. Palette reuse changes line patterns or scatter symbols; split charts with more than eight series when possible. Authors should check custom palettes for background contrast and color-vision differences. Heatmaps use a sequential, single-hue gradient with monotone lightness.

## Persistent Output and Chart Styles

The last successful output stays visible while a cell reruns, including the 150ms reactive debounce. A small updating indicator does not move the layout. Failed reruns keep that output alongside an error and a **Retry cell** action; cancellation and invalid inputs also retain it. Success replaces the result and clears the error. Use explicit artifact IDs when an output sequence changes dynamically: IDs retain identity across insertions, duplicate IDs receive occurrence numbers, and artifacts without IDs are matched by kind and occurrence.

Compatible charts update the existing canvas and ECharts instance, preserving the reader's zoom window. Initial and data-update transitions use 180ms with cubicOut easing. Structural changes replace chart options on the same instance; Starlight light/dark theme changes merge colors and typography without resetting reader interactions. A chart update failure keeps the last successful visualization and summary with a local retry action. Reduced-motion preferences disable chart and updating-indicator animation, even when an author requests animation.

Chart specs accept an optional nested `style` object:

```ts
interface ChartPalette {
  light?: readonly string[];
  dark?: readonly string[];
}
interface BaseChartStyle {
  height?: number;
  palette?: ChartPalette;
  showGrid?: boolean;
  animation?: boolean;
  animationDurationMs?: number;
}
interface LineChartStyle extends BaseChartStyle {
  lineWidth?: number;
}
interface ScatterChartStyle extends BaseChartStyle {
  symbolSize?: number;
}
```

Line and area charts use `LineChartStyle`, scatter charts use `ScatterChartStyle`, and bar, histogram, and heatmap charts use `BaseChartStyle`.

| Field                 | Allowed values and default                                                                                                                                                                         |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `palette`             | At least one of `light` or `dark`; each supplied theme has 1–12 unique `#RGB` or `#RRGGBB` colors. Heatmaps require at least two. Colors are compared after expanding shorthand and ignoring case. |
| `showGrid`            | Boolean; default `true`.                                                                                                                                                                           |
| `height`              | Integer from 200 to 800 pixels. Default 360; heatmaps automatically use 240–720 pixels based on row count.                                                                                         |
| `animation`           | Boolean; default `true`, subordinate to reduced motion.                                                                                                                                            |
| `animationDurationMs` | Integer from 0 to 2,000; default 180 for both initial and update animation.                                                                                                                        |
| `lineWidth`           | Finite number from 1 to 8; default 2.25. Line and area only.                                                                                                                                       |
| `symbolSize`          | Finite number from 2 to 32; default 7. Scatter only.                                                                                                                                               |

Palettes color series, or the visual-map gradient for heatmaps. A missing theme palette uses the Oxiquill default for that theme. Chart chrome and typography follow Starlight. Unknown nested fields, fields for another chart kind, raw ECharts options, callbacks, formatters, and HTML are rejected. Style contributes to the normal artifact byte budget; it does not bypass output limits.

Every existing Rust chart macro signature remains valid. These overloads add a final JSON-serializable style argument, such as `&serde_json::json!({ "lineWidth": 3 })`:

```text
emit_line_chart!(series, style)
emit_line_chart!(series, x_label, y_label, style)
emit_scatter_chart!(series, style)
emit_scatter_chart!(series, x_label, y_label, style)
emit_bar_chart!(categories, values, style)
emit_histogram!(bins, style)
emit_heatmap!(data, style)
emit_line_plot!(points, x_label, y_label, style)
```

The macro serializes the argument into `spec.style`; normal chart validation enforces the same contract.

### Numeric formats

Set `style.xFormat` or `style.yFormat` on value/log axes; heatmaps use `style.valueFormat` for their color scale. The same settings format ticks, pointers, tooltips, and summaries. Category and time axes retain their own formatting.

Each format accepts `significantDigits` (integer 1–17), `fractionDigits` (integer 0–20), `unit` (text), and `notation` (`auto` or `si`). The two precision fields are mutually exclusive. Fixed decimals keep trailing zeros and may round small values to zero; negative zero displays as zero. Without overrides the default formatting remains in effect. Removing a format restores it.

Units follow numbers; axis names remain in `xLabel/yLabel`. SI chooses one prefix from the data range (10⁻²⁴ through 10²⁴), including rounding at prefix boundaries, and falls back to scientific notation outside that range. Formatting never changes stored values. No callbacks, format strings, HTML, or raw ECharts options are accepted.

```rust
//| id: formatted-voltage
//| title: Voltage measurements
let points = [[0.0, 1500.0], [1.0, 2400.0]];
emit_line_chart!(&points, "Time", "Voltage", &serde_json::json!({
    "xFormat": { "fractionDigits": 1, "unit": "s" },
    "yFormat": { "significantDigits": 3, "notation": "si", "unit": "V" }
}));
```

### Series identity and style

XY and bar series accept an optional non-empty, unique `id`. Give a series the same ID on each execution to preserve its identity and legend selection when reordering or renaming it. Names are display labels; even same-named series can be selected independently. Without IDs, identity follows the series index. Adding or removing series does not reset zoom. Default palette colors still follow authored order; use explicit colors when a series needs a fixed color.

Set `series.style.color` to a `#RGB/#RRGGBB` string or `{ light, dark }` with at least one theme. An omitted theme uses the chart palette. Line/area series also accept `lineType` (solid/dashed/dotted), `step` (false/start/middle/end), `smooth` (boolean), `symbol`, and `showSymbol`. Scatter supports color and symbol; bar supports color. Symbols are circle/emptyCircle/rect/triangle/diamond/none.

Smooth and step cannot both be enabled. Lines remain unsmoothed by default. Explicit patterns and symbols override palette cycling, and explicit showSymbol overrides isolated-point detection. Removing settings restores defaults. Existing chart-level lineWidth and symbolSize continue to control sizes.

```rust
//| id: styled-series
//| title: Measured and reference series
let series = serde_json::json!([
    { "id": "measured", "name": "Measurement", "points": [[0, 1], [1, 2]],
      "style": { "color": { "light": "#3987e5", "dark": "#9085e9" }, "symbol": "diamond", "showSymbol": true } },
    { "id": "reference", "name": "Reference", "points": [[0, 1.5], [1, 1.5]],
      "style": { "lineType": "dashed", "step": "end" } }
]);
emit_line_chart!(&series, "Observation", "Value");
```

## Resource Limits

Producers enforce limits inside each language worker before `postMessage`; the main thread independently validates the bounded response again. Limits are UTF-8 byte limits and are cumulative for each run where noted:

| Resource                    | Limit                           | Over-limit result                                                 |
| --------------------------- | ------------------------------- | ----------------------------------------------------------------- |
| Artifacts                   | 100 per run                     | Additional artifacts are rejected locally.                        |
| stdout or stderr            | 1 MiB per stream                | Captured text is retained only to the limit and marked truncated. |
| Text, serialized JSON, HTML | 1 MiB per artifact              | Text/JSON may use `truncated: true`; HTML is rejected.            |
| Table                       | 10,000 rows and 100 columns     | A bounded table may use `truncated: true` and `rowCount`.         |
| Chart                       | 100,000 total points/bins/cells | Artifact-local error.                                             |
| Image                       | 10 MiB decoded bytes            | Artifact-local error.                                             |
| All validated output        | 16 MiB per run                  | Artifacts exceeding the remaining budget are rejected locally.    |
| Complete worker response    | 16 MiB                          | Later artifacts are omitted before worker-to-page transfer.       |
| Worker error                | 16 KiB                          | The UTF-8 message is truncated.                                   |
| Artifact diagnostic         | 8 KiB each; 64 KiB per run      | Diagnostics are truncated within both limits.                     |

`truncated: true` is valid only for text, JSON, and table artifacts. Chart, image, and HTML artifacts are never silently truncated. Invalid/cyclic/over-deep JSON, ragged tables, non-finite chart values, invalid base64/MIME pairs, or unsafe structural records cannot crash the cell component. Execution results contain only `outputs`; stream text and JSON values are artifacts rather than duplicate top-level fields.

## Chart images

**Show data as a table** exposes the original values, including hidden series, histogram boundaries and counts, and heatmap coordinates. Whole epoch milliseconds on time axes appear as the UTC ISO-8601 instants the chart displays. Conversion occurs only when opened and retains at most 10,000 rows; totals and truncation are shown. The table supports keyboard sorting, paging, and CSV download. Series buttons show their selection with `aria-pressed` and use color, line pattern, and symbols. **Reset zoom** restores the authored full range without resetting series selections. These controls are usable with the keyboard; chart summaries remain available to assistive technology.

Use **Save PNG** or **Save SVG** to download the current chart with its theme, zoom, series selection, and heatmap color range. PNG uses twice the plot's width and height in pixels; SVG retains the plot's logical dimensions. Both include the plot background and legend, without animation, title, or caption. Saving uses a temporary renderer and does not replace the displayed chart.

Authors may select `style: { renderer: "svg" }` in a chart spec, including through Rust chart style arguments and Python `display_chart`. The default remains `"canvas"`. SVG provides vector output for scaling and printing; it is not always faster for large datasets. Print output retains the chart and caption while hiding action buttons.

## CSV Copy Safety

**Save all retrieved rows as CSV** downloads every retained row in the current sort order, across all pages. **Copy visible rows as CSV** copies only the current page. When a result is truncated, the download contains only the retrieved portion, not the larger reported row count. Downloads work without clipboard access and preserve original numeric values.

Tables display every digit of integers up to ±9,007,199,254,740,991 (`Number.MAX_SAFE_INTEGER`), the largest range in which every integer is exact. Larger values and non-integers use six significant digits, with scientific notation at absolute values of at least `1e6` or below `1e-4`. Negative zero displays as `0`. Grouping separators appear only when a column contains an absolute value of at least 10,000, consistently across pages. Hover a numeric cell to inspect its original value. Sorting and CSV use original values.

The default table action copies visible rows as spreadsheet-safe CSV. String headers or cells whose first meaningful character is `=`, `+`, `-`, `@`, tab, or carriage return receive a leading apostrophe before RFC-style comma/quote/line-break escaping. This deterministic convention prevents common spreadsheet applications from evaluating string data as a formula. Numeric values remain numeric, so a genuine number such as `-42` is copied as `-42`.

## Execution result migration

**Breaking change:** execution results now require an `outputs` array. Top-level `stdout/stderr/value/plots` and the public `PlotSpec/LinePlotSpec` types have been removed. `JsonArtifact.value` and input `value` fields remain supported.

Previously, an explicit `outputs` field took precedence even when empty; only its absence triggered conversion in stdout, stderr, value, plots order. Legacy-only results and non-array outputs now produce a regeneration diagnostic. Obsolete fields alongside an outputs array are ignored.

```typescript
const result = {
  outputs: [
    { kind: 'text', stream: 'stdout', content: 'Printed output' },
    { kind: 'text', stream: 'stderr', content: 'Diagnostic output' },
    { kind: 'json', value: { answer: 42 } },
    { kind: 'chart', spec: { kind: 'line', series: [{ points: [[0, 1]] }] } }
  ]
};
```

Rust early returns must also supply explicit artifacts. Normal output still uses `println!` and `emit_*`.

```rust
return Ok(CellOutput {
    outputs: vec![OutputArtifact::Text(TextArtifact {
        stream: "stdout",
        content: "Early return".to_owned(),
        truncated: false,
    })],
});
```

The optional `doc-rust` helper crate also removes `PlotSpec/LinePlot/line_plot`. Convert `SeriesPoint` explicitly to `[f64::from(point.n), point.x]` and pass the coordinates to `emit_line_chart!`. The compatibility macro `emit_line_plot!` remains available.

Ordering is unchanged: Rust emits captured stdout followed by artifacts in emit order; Python emits stdout, stderr, display artifacts, automatically collected matplotlib figures, then the final value; Haskell emits stdout then stderr. Python omits an implicit final JSON value for None or an empty string. Explicit JSON artifacts retain null, empty strings, false, and zero. Stream capture does not interleave with display calls.

After upgrading, regenerate the runtime with `pnpm exec oxiquill docgen --wasm dev` or the production `pnpm build`. Do not edit generated files directly.

## Python Display Helpers

Python cells include display helpers:

- `display(value)` chooses JSON, table, image, HTML, or text output from the value.
- `display_json(value)` emits JSON.
- `display_html(html)` emits sandboxed HTML.
- `display_table(rows_or_dataframe)` emits a table.
- `display_image(data, mime)` emits SVG, PNG, or JPEG image data.

The runtime also understands common rich representations such as pandas DataFrames and Series, matplotlib figures, `_repr_mimebundle_`, `_repr_json_`, `_repr_html_`, `_repr_svg_`, `_repr_png_`, and `_repr_jpeg_`.

**Display migration:** matplotlib starts each cell with the chart palette, sans-serif text, light grid lines, fewer frame lines, and a white background. Figures remain white paper in dark mode. Override `matplotlib.rcParams` inside the cell, or call `matplotlib.rcdefaults()` before creating figures to restore upstream defaults.

Each cell resets style settings before applying these defaults, so a previous cell's `plt.style.use("dark_background")` does not affect it. Grid lines also appear over images from `imshow`; call `ax.grid(False)` for photographs and heatmaps when you do not want that overlay.

Figure titles and axis labels supply image alternative text. SVG text uses browser fonts (`svg.fonttype: 'none'`), including Japanese fallback fonts installed on the reader's device. SVG larger than 10 MiB falls back to PNG at 150 DPI with a stderr diagnostic. PNG rendering needs fonts in the Python environment to draw Japanese glyphs. Image and cumulative run budgets still apply; oversized PNG output produces an artifact error.

`display_chart(spec, *, id=None, title=None, caption=None)` emits any of the six interactive chart kinds using only dict/list data, without pandas. Pass style inside the spec and artifact metadata separately.

`display_line(df, *, x, y, id=None, title=None, caption=None, style=None)` builds a line chart from DataFrame columns. `y` is a column name or a nonempty list of distinct column names. Row and column order are preserved, with at most 100,000 points across all series. X values may be numbers, string categories, or timezone-aware datetimes; Y values must be finite numbers. Datetimes become UTC epoch milliseconds. Missing values, NaN, infinity, NaT, and naive datetimes produce a local error identifying the row position and column. Valid neighboring outputs remain visible; missing values are never silently connected.

```python
display_chart({
    "kind": "area",
    "series": [{"points": [[0, 1], [1, 2]]}],
    "style": {"animation": False},
}, id="area", title="Measurements", caption="Two samples")

import pandas as pd
values = pd.DataFrame({"time": [0, 1], "a": [1, 2], "b": [3, 4]})
display_line(values, x="time", y=["a", "b"], title="Two series")
```

```python
#| id: python-rich-outputs
#| title: Python table, matplotlib, HTML, and JSON outputs
#| run: button
#| timeoutMs: 120000
#| packages: [matplotlib, pandas]
import pandas as pd
import matplotlib.pyplot as plt

scores = pd.DataFrame({"label": ["alpha", "beta", "gamma"], "score": [3, 5, 4]})

display(scores, title="Pandas table")
display_json({"status": "ok", "rows": len(scores)}, title="Summary")
display_html("<p><strong>Sandboxed HTML</strong> emitted from Python.</p>", title="HTML")

plt.bar(scores["label"], scores["score"])
_ = plt.title("Scores")
_ = plt.xlabel("label")
_ = plt.ylabel("score")
```

## Rust Output Macros

Rust cells use explicit `emit_*` macros. Supported macros include:

- `emit_text!`
- `emit_json!`
- `emit_html!`
- `emit_svg!` and `emit_image_svg!`
- `emit_png_base64!` and `emit_image_png!`
- `emit_table!`, `emit_table_with_columns!`, and `emit_records_table!`
- `emit_chart!`, `emit_area_chart!`, `emit_line_chart!`, `emit_scatter_chart!`, `emit_bar_chart!`, `emit_histogram!`, and `emit_heatmap!`
- `emit_line_plot!` for compatibility with the original line-plot helper; new code should convert coordinates explicitly and use `emit_line_chart!`.

`emit_chart!(spec)` accepts all six chart kinds. Optional `metadata = ...` supplies artifact `id/title/caption`, separately from spec `title/xLabel/yLabel`; the artifact title takes display precedence. Null metadata fields are omitted, and other metadata fields produce a local diagnostic. `emit_area_chart!` accepts the same points/series, axis labels, trailing style, and `options = ...` forms as line charts. Existing macro argument forms remain supported. An invalid spec produces a local diagnostic while valid neighboring outputs remain visible.

```rust
emit_chart!(serde_json::json!({
    "kind": "area",
    "title": "Spec title",
    "xLabel": "Time",
    "yLabel": "Value",
    "series": [{ "points": [[0, 1], [1, 2]] }],
    "style": { "animation": false }
}), metadata = serde_json::json!({
    "id": "measurements", "title": "Measurement report", "caption": "Two samples"
}));
emit_area_chart!(&[[0, 1], [1, 2]], "Time", "Value");
```

```rust
//| id: rust-rich-outputs
//| title: Rust table, chart, JSON, SVG, and HTML outputs
//| run: button
//| crates: []
let rows = vec![
    serde_json::json!({"label": "alpha", "score": 3}),
    serde_json::json!({"label": "beta", "score": 5}),
    serde_json::json!({"label": "gamma", "score": 4}),
];
let columns = vec![
    serde_json::json!({"key": "label", "label": "Label", "type": "string"}),
    serde_json::json!({"key": "score", "label": "Score", "type": "integer"}),
];
let heatmap = [[0, 0, 1], [1, 0, 3], [0, 1, 2], [1, 1, 4]];

emit_json!(&serde_json::json!({"status": "ok", "rows": rows.len()}));
emit_records_table!(&rows);
emit_table_with_columns!(&columns, &rows);
emit_bar_chart!(&["alpha", "beta", "gamma"], &[3, 5, 4], &serde_json::json!({
    "palette": { "light": ["#7c3aed"], "dark": ["#c4b5fd"] },
    "animationDurationMs": 180
}));
emit_heatmap!(&heatmap);
emit_svg!(
    r##"<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 160 48"><rect width="160" height="48" fill="#ecfeff"/><circle cx="32" cy="24" r="14" fill="#0f766e"/><rect x="64" y="12" width="72" height="24" rx="4" fill="#2563eb"/></svg>"##,
    "Simple generated SVG"
);
emit_html!(r#"<p><strong>Sandboxed HTML</strong> emitted from Rust.</p>"#);
```

## When to Use Rich Output

Use stdout for short explanatory text. Use JSON when readers need the exact structured value. Use tables for comparable records, charts for trends or distributions, images for generated visuals, and sandboxed HTML only when the output needs markup that cannot be represented by the other artifact types.

Copy, sort, pagination, validation, running, completion, and failure states are keyboard-operable and announced with localized English/Japanese labels. Sandboxed HTML intentionally has no script or same-origin permission, sends no referrer, and blocks external subresources by default; see [Support and Security](/guides/support-and-security/) for the exact policy and trust boundary.

Table interaction state is scoped to one execution result. A new result resets the page, sort, and copy status. Rerenders of the same result preserve a compatible sort and page, but row shrinkage stores the clamped page and a removed or replaced sorted column clears the sort.

## Stacked charts

Bar and area series accept a nonempty `stack` group. Positive and negative values accumulate separately from zero on a value axis. Missing bar values do not contribute. Area series in each group must have identical, ordered X coordinates; numeric/time coordinates must increase. Tooltips and data tables retain the individual values. Percent normalization is not performed.

```rust
//| id: stacked-charts
//| crates: []
let series = serde_json::json!([
    { "name": "First", "stack": "total", "points": [[0, 2], [1, -2]] },
    { "name": "Second", "stack": "total", "points": [[0, 3], [1, -3]] }
]);
emit_area_chart!(&series, "Observation", "Amount");
emit_bar_chart!(&["A", "B"], &serde_json::json!([
    { "name": "First", "stack": "total", "values": [2, -2] },
    { "name": "Second", "stack": "total", "values": [3, null] }
]));
```

## Horizontal bars

Set bar `orientation: "horizontal"` to use a numeric x axis and category y axis. Labels, formats, and bounds refer to screen axes. The first category appears at the top. Missing values, multiple series, and stack groups work in either orientation.

```rust
//| id: horizontal-bars
//| crates: []
emit_bar_chart!(&["North America", "South America", "Europe"], &[12, -4, 8],
    options = serde_json::json!({ "orientation": "horizontal", "xLabel": "Change", "yLabel": "Region" }));
```

## Error bars and interval bands

Use `errorbar` or `band` with `[x, center, lower, upper]` points satisfying `lower <= center <= upper`. Set all three Y values to null for a gap. Bands connect adjacent valid points with straight segments and require increasing value/time/log X coordinates. Y uses value or log; log intervals must be positive. Statistical estimation belongs in the cell. A single isolated band point is shown as an interval glyph. Chart and series colors follow the existing styles; interval charts also accept chart-level `lineWidth`.

```python
#| id: interval-charts
for kind in ("errorbar", "band"):
    display_chart({"kind": kind, "xLabel": "Observation", "yLabel": "Estimate",
        "series": [{"name": "Estimate and interval", "points": [
            [0, -3, -5, -2], [1, 0, -2, 3], [2, 4, 3, 6]]}]})
```
