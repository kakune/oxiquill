---
title: Interactive Cells
description: Configure Rust, Python, and Haskell cells that execute on the static site.
---

Interactive cells are ordinary MDX code blocks with metadata comments at the top. Oxiquill extracts those blocks during generation and replaces them with a runtime UI.

Rust cells are compiled to WebAssembly at build time. Python cells run in a browser Pyodide worker. Haskell cells are compiled to a WASI WebAssembly module at build time. All three languages use the same input metadata and run-mode model.

## Cell Metadata

Metadata must be one contiguous block of language-appropriate option comments at the very beginning of the code block. Rust uses `//|` or `///|`, Python uses `#|`, and Haskell uses `--|`. An option-looking line after source code begins remains source code.

Only these top-level fields are allowed:

- `id`: required page-local ID matching `^[a-z][a-z0-9]*(?:-[a-z0-9]+)*$`.
- `title`: string shown in the cell header; defaults to `id`.
- `run`: `button`, `reactive`, or `autorun`; defaults to `button`.
- `inputs`: mapping of input names to input definitions; omitted by default and forbidden for `autorun`.
- `timeoutMs`: positive integer execution timeout in milliseconds; defaults to `30000`.
- `showSource`: boolean controlling initial source visibility; defaults to `true`.
- `crates`: unique non-empty helper crate names; Rust only.
- `packages`: unique non-empty vendored Pyodide package names; Python only.

Unknown fields, duplicate dependency names, wrong scalar or collection types, unsupported packages, and unknown helper crates stop generation with a page, fence line, cell ID, and field-specific diagnostic. Haskell cells use standard-library code only and support neither dependency field.

## Run Modes

- `button`: the reader starts execution explicitly.
- `reactive`: the cell runs initially and reruns when inputs change.
- `autorun`: the cell runs automatically once and remains available for manual reruns.

## Inputs

Supported input types are `range`, `number`, `integer`, `text`, `textarea`, `checkbox`, `select`, and `radio`.

Input names are available as variables inside the cell and must match `^[a-z][a-z0-9_]*$`. Each definition is a mapping containing only `type`, `label`, `value`, `min`, `max`, `step`, `integer`, and `options`:

- `type` defaults to `text`; `label` defaults to the input name.
- Defaults are `false` for checkbox, `0` for numeric inputs, and an empty string for text inputs. Explicit values must have exactly that scalar type.
- Numeric `min`, `max`, and `step` must be finite. `step` must be positive, `min` must not exceed `max`, and the default must be within the bounds. An `integer` input, or a numeric input with `integer: true`, requires integer values and constraints.
- `select` and `radio` require a string default and a non-empty list of unique option values. An option is either a non-empty string or a `{ label, value }` mapping containing two non-empty strings. The default must match an option value.
- Numeric-only fields are rejected on non-numeric controls, and `options` is rejected outside `select` and `radio`.

Reserved Rust or Haskell words are converted to safe generated bindings. Generation rejects names that would collide after this conversion.

## Rust and Plots

This Rust cell uses a helper crate and redraws a plot whenever the sliders change.

```rust
//| id: logistic-rust
//| title: Calculate the logistic map with Rust
//| run: reactive
//| crates: [doc-rust]
//| inputs:
//|   r: { type: range, label: r, min: 0, max: 4, step: 0.01, value: 3.2 }
//|   x0: { type: range, label: x0, min: 0, max: 1, step: 0.01, value: 0.2 }
//|   steps: { type: integer, label: steps, min: 10, max: 300, step: 10, value: 120 }
let points = doc_rust::logistic_series(r, x0, steps).map_err(|error| error.to_string())?;

for point in points.iter().take(5) {
    println!("n={} x={:.6}", point.n, point.x);
}

emit_line_plot!(&points, "n", "x");
```

## Rust Input UI

A cell with `crates: []` does not depend on helper crates. This example shows checkbox, select, and radio inputs.

```rust
//| id: rust-controls
//| title: Rust input UI
//| run: reactive
//| crates: []
//| inputs:
//|   include_bonus: { type: checkbox, label: include bonus, value: true }
//|   operation: { type: select, label: operation, value: double, options: [identity, double, triple] }
//|   style: { type: radio, label: style, value: compact, options: [compact, verbose] }
let base_score = match operation.as_str() {
    "triple" => 21_u32,
    "double" => 14_u32,
    _ => 7_u32,
};
let score = if include_bonus {
    base_score + 5
} else {
    base_score
};

println!("style = {style}");
println!("score = {score}");
```

## Multiple Rust Helper Crates

Each Rust cell declares the helper crates it needs. The names must match Cargo package names under `crates/*`.

```rust
//| id: rust-multiple-crates
//| title: Rust cell with multiple crates
//| run: reactive
//| crates: [doc-rust, doc-rust-text]
//| inputs:
//|   style: { type: radio, label: style, value: compact, options: [compact, verbose] }
let points = doc_rust::logistic_series(3.2, 0.2, 8).map_err(|error| error.to_string())?;
let final_point = points.last().ok_or_else(|| "series is empty".to_owned())?;

println!("{}", doc_rust_text::labeled_value("final step", final_point.n));
println!("{}", doc_rust_text::labeled_value("final x", format!("{:.6}", final_point.x)));
println!("{}", doc_rust_text::style_note(style.as_str()));
```

## Python Inputs

Python cells use the same input metadata. Input values are available as Python variables.

```python
#| id: python-controls
#| title: Python input UI
#| run: reactive
#| inputs:
#|   scale: { type: number, label: scale, min: 1, max: 10, step: 1, value: 3 }
#|   label: { type: text, label: label, value: "sample" }
#|   enabled: { type: checkbox, label: include uppercase, value: true }
#|   method: { type: select, label: method, value: mean, options: [mean, sum, max] }
#|   style: { type: radio, label: style, value: compact, options: [compact, verbose] }
values = [1, 2, 3, 4]

if method == "sum":
    result = sum(values) * scale
elif method == "max":
    result = max(values) * scale
else:
    result = sum(values) / len(values) * scale

name = label.upper() if enabled else label
print(f"{name}: {method} = {result}")
print(f"style = {style}")
```

## Haskell Inputs

Haskell cells use `--|` metadata comments. Input values become Haskell variables, and text output written with `putStrLn` or `print` appears in the result panel.

```haskell
--| id: haskell-controls
--| title: Haskell input UI
--| run: reactive
--| inputs:
--|   factor: { type: integer, label: factor, min: 1, max: 5, step: 1, value: 3 }
--|   label: { type: text, label: label, value: sample }
--|   include_squares: { type: checkbox, label: include squares, value: true }
import Data.List (intercalate)

let base = [1 .. 4 :: Int]
let scaled = map (* factor) base
let displayed = if include_squares then map (\value -> value * value) scaled else scaled

putStrLn (label ++ ": " ++ intercalate ", " (map show displayed))
putStrLn ("total = " ++ show (sum displayed))
```
