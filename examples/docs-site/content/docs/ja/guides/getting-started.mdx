この guide は、ドキュメントサイトをローカルで動かすとき、または docs 変更が build できるか確認するときに使います。

## 前提

作業前に次の tool を用意します。

- Node.js と `pnpm`
- Rust toolchain `1.95.0`
- `wasm-pack`
- `cargo-llvm-cov`
- Haskell セルを書く場合は `wasm32-wasi-ghc`

Rust toolchain と Wasm target は `rust-toolchain.toml` で固定されています。通常のドキュメント作業で toolchain を変更しないでください。Haskell セルは GHC の `wasm32-wasi` backend を使い、通常は `ghc-wasm-meta` で導入します。`~/.ghc-wasm/env` は toolchain を有効化します。Oxiquill command では、`PATH` 全体を変えずに `OXIQUILL_HASKELL_GHC` で `wasm32-wasi-ghc` を指定することもできます。ghc-wasm の static Node が `PATH` の先頭にある場合は、Astro/Vite subprocess 用に `OXIQUILL_NODE` で通常の Node.js binary を指定してください。

## 依存関係を入れる

```sh
pnpm install
```

依存関係には Astro、Starlight、Preact、Pyodide、Mermaid、KaTeX、Vitest、Playwright、実行可能セル runtime を生成する `oxiquill` CLI が含まれます。

## Consumer repository を作る

別の documentation repository では、Oxiquill と Astro および Starlight の framework dependency を指定し、script は Oxiquill CLI に委譲します。

```json
{
  "dependencies": {
    "@astrojs/starlight": "0.41.9",
    "astro": "7.2.9",
    "oxiquill": "0.2.0"
  },
  "scripts": {
    "dev": "oxiquill dev",
    "build": "oxiquill build",
    "check": "oxiquill check"
  }
}
```

`link:`、workspace、Git dependency、submodule 形式でも同じ setup を使い、dependency specifier だけを変えます。consumer config は次の形です。

```js
import starlight from '@astrojs/starlight';
import { defineOxiquillConfig } from 'oxiquill/astro';

export default defineOxiquillConfig({
  framework: { starlight },
  title: 'My Docs',
  sidebar: [{ label: 'Overview', items: [{ label: 'Home', slug: 'index' }] }]
});
```

```ts
import { defineCollection } from 'astro:content';
import { docsLoader } from '@astrojs/starlight/loaders';
import { docsSchema } from '@astrojs/starlight/schema';
import { createOxiquillCollections } from 'oxiquill/content';

export const collections = createOxiquillCollections({ defineCollection, docsLoader, docsSchema });
```

## 開発サーバーを起動する

```sh
pnpm dev
```

dev command は runtime 生成から始まり、その後 docs と helper source を監視します。

- 本文、通常 code block、数式、Mermaid、メディアの変更は Astro HMR で更新されます。
- Python セルの変更は生成 cell manifest を更新します。
- Rust セルや `crates/*` の変更は生成 Wasm runtime を再ビルドします。
- Haskell セルの変更は、Haskell セルがある場合に生成 WASI runtime を再ビルドします。

Haskell compiler がない、または Haskell セルの build に失敗した場合でも、`pnpm dev` と `pnpm dev:runtime` は serving を続け、browser 上の Haskell セルに error を表示します。`pnpm build`、`pnpm check`、`pnpm wasm:dev`、`pnpm wasm:build`、`pnpm test:wasm` などの strict command は、`wasm32-wasi-ghc` が利用でき、セルが build できるまで失敗します。

runtime 生成を Astro と分けて確認したい場合は、次の command を別々の terminal で実行します。

```sh
pnpm dev:runtime
pnpm dev:astro
```

## 静的出力をビルドする

```sh
pnpm build
```

build は Wasm runtime build、Astro check、静的サイトの `dist/` 出力を実行します。

## build 結果を確認する

```sh
pnpm preview
```

development server ではなく production output を確認したいときは、`pnpm build` の後に preview を使います。

## 生成物

runtime generation は次の path に生成物を書きます。

- `.oxiquill/generated`
- `.oxiquill/rust-cells`
- `.oxiquill/haskell-cells`
- `public/oxiquill/pyodide`
- `public/oxiquill/rust-wasm`
- `public/oxiquill/haskell-wasm`
- `public/oxiquill/licenses`
- `dist`

これらの path を直接編集しないでください。MDX、helper crate、script、手書き runtime code を変更してから既存 command で再生成します。
