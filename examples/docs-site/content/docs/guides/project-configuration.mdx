title: Project Configuration
description: Configure Astro, Starlight, Oxiquill paths, and generated output without splitting project state.
---

Oxiquill loads one project configuration and uses the same resolved paths for development, checks, generation, builds, tests, and cleanup. Keep `astro.config.mjs` at the project root unless every command receives the same `--config` option.

## Minimal Configuration

```js
import starlight from '@astrojs/starlight';
import { defineOxiquillConfig } from 'oxiquill/astro';

export default defineOxiquillConfig({
  framework: { starlight },
  site: 'https://example.com',
  title: 'My Docs',
  sidebar: [{ label: 'Overview', items: [{ label: 'Home', slug: 'index' }] }]
});
```

```ts
// content.config.ts
import { defineCollection } from 'astro:content';
import { docsLoader } from '@astrojs/starlight/loaders';
import { docsSchema } from '@astrojs/starlight/schema';
import { createOxiquillCollections } from 'oxiquill/content';

export const collections = createOxiquillCollections({ defineCollection, docsLoader, docsSchema });
```

`defineOxiquillConfig()` returns an Astro configuration with static output, Oxiquill's Markdown transforms, Preact, and Starlight already installed.

## Configuration Fields

| Field                             | Meaning                                                                                                                                                 |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `title`, `description`, `sidebar` | Shorthand for the corresponding Starlight settings.                                                                                                     |
| `desktopTableOfContentsToggle`    | Enables the persistent desktop table-of-contents control. Defaults to `true`.                                                                           |
| `starlight`                       | Any other Starlight option. A value here overrides the matching shorthand.                                                                              |
| `framework.starlight`             | Required Starlight integration factory imported from `@astrojs/starlight`.                                                                              |
| `framework.preact`                | Optional Preact integration-factory override for embedded/framework consumers.                                                                          |
| `integrations`                    | Additional Astro integrations, appended after Oxiquill, Preact, and Starlight.                                                                          |
| `markdown`                        | Supported Astro Markdown settings and plugins. Oxiquill's required plugins run first.                                                                   |
| `vite`                            | Additional Vite settings. Oxiquill preserves required aliases, deduplication, worker plugins, and filesystem access.                                    |
| `paths`                           | Oxiquill-owned source, cache, generated, and public paths described below.                                                                              |
| `python`                          | Pyodide download behavior: `preload`, `offline`, and the optional `packageMirror`.                                                                      |
| `rust`                            | Rust compilation grouping: `site` (default) or `page`.                                                                                                  |
| `missingTranslations`             | `fallback` (default) keeps Starlight's fallback pages; `omit` generates and links only translated pages. See [Multilingual Sites](#multilingual-sites). |
| `docRedirects`                    | Redirects whose destinations are base-relative documentation paths. See [Document Redirects](#document-redirects).                                      |
| Other Astro fields                | Passed through to Astro. Oxiquill always produces static output.                                                                                        |

Use `oxiquillIntegration()` only when composing an Astro configuration manually. It accepts `base`, `markdown`, `paths`, `python`, `rust`, and `vite`; the caller is then responsible for adding Preact and Starlight. `missingTranslations` and `docRedirects` also configure Starlight and Astro, so only `defineOxiquillConfig()` accepts them.

Oxiquill owns `markdown.processor` because interactive cells, Mermaid, KaTeX, and public-asset base paths require its unified pipeline. A custom processor is not supported and throws a `TypeError`; configure supported Markdown fields and append `remarkPlugins` or `rehypePlugins` instead.

## Desktop Table of Contents

On pages with a table of contents, Oxiquill adds a desktop collapse/expand button while preserving Starlight's mobile disclosure. Collapsing the table of contents removes the complete right column and lets the main content use the released width. The preference is stored for the current browser tab in `sessionStorage` under `oxiquill-table-of-contents-collapsed`; it is independent from the left-sidebar preference.

Set `desktopTableOfContentsToggle: false` to retain Starlight's always-visible desktop table of contents:

```js
export default defineOxiquillConfig({
  desktopTableOfContentsToggle: false,
  framework: { starlight },
  title: 'My Docs'
});
```

The control is not rendered for `tableOfContents: false` or splash pages. Consumer entries in `starlight.components` take precedence over Oxiquill's defaults, including `PageFrame`, `TableOfContents`, and `TwoColumnContent` overrides.

The table-of-contents column is `--oq-toc-width` wide. The default, `clamp(14rem, 18vw, var(--sl-sidebar-width))`, narrows the column on small desktops so the content keeps more of its measure and reaches the sidebar width on large screens. Wider screens divide the remaining space between the content and the table of contents, keeping both near the center. Long entries wrap inside the column, and the toggle sits on the column border at every width. Set the property on `:root` to choose a fixed width:

```css
:root {
  --oq-toc-width: 16rem;
}
```

The property applies to Oxiquill's toggle layout. With `desktopTableOfContentsToggle: false`, Starlight's own column sizing remains.

## Content Width

Collapsing the left sidebar adds `--sl-sidebar-width` to the current `--sl-content-width`, and collapsing the table of contents adds its column width, `--oq-toc-width`. The default reading measure stays the same when both columns are expanded.

To customize the measure and column size, register a stylesheet with `starlight.customCss`, for example `starlight: { customCss: ['./styles/custom.css'] }`. It loads after Oxiquill's CSS. Set both properties on `:root`:

```css
:root {
  --sl-content-width: 80rem;
  --sl-sidebar-width: 20rem;
}
```

Fluid values such as `--sl-content-width: 100%` stay fluid through every toggle state. Starlight gives pages without a sidebar, including splash pages, a separate base measure. Override that measure with `:root:not([data-has-sidebar]) { --sl-content-width: 100%; }` when needed.

A page can drop the reading measure without changing the rest of the site. Set `contentWidth: full` in its frontmatter; the content then fills the space between the navigation columns, and both toggles keep working. Use it for wide reference tables or several charts, and keep prose pages at the default measure.

```mdx
---
title: API Index
contentWidth: full
---
```

`createOxiquillCollections()` adds `contentWidth` (`default` or `full`) to the docs schema. A project with its own docs schema needs the same optional field.

A custom `PageFrame` keeps table-of-contents widening through Oxiquill's `TwoColumnContent`, but sidebar widening requires Oxiquill's `PageFrame`.

## Multilingual Sites

Starlight fills untranslated pages with default-locale content, called fallback pages, so every locale has every route. Set `missingTranslations: 'omit'` when a locale should contain only translated pages:

```js
export default defineOxiquillConfig({
  framework: { starlight },
  missingTranslations: 'omit',
  starlight: {
    defaultLocale: 'root',
    locales: {
      root: { label: 'English', lang: 'en' },
      ja: { label: '日本語', lang: 'ja' }
    }
  }
});
```

Oxiquill removes fallback routes before Astro generates pages, so they produce no HTML, sitemap entry, or search record, and the development server answers them with 404. Navigation follows the generated pages:

- The language select lists only locales that have the current page and is hidden when no other locale does.
- The sidebar drops links to untranslated pages and the groups that become empty.
- Previous and next links skip untranslated pages; `prev` and `next` frontmatter still applies.
- `hreflang` alternates and the site title link point only at generated pages.

The default, `'fallback'`, keeps Starlight's behavior. Omit mode requires prerendered Starlight pages, which is the default. It adds Oxiquill's `LanguageSelect` component and a route middleware: a `LanguageSelect` entry in `starlight.components` takes precedence, and entries in `starlight.routeMiddleware` run after Oxiquill's and see the filtered navigation.

## Document Redirects

Astro matches `redirects` sources below `base`, but it leaves a destination unprefixed when it cannot see a matching route. Pages served by Starlight are such destinations. Use `docRedirects` for moved documentation pages. Each destination is a base-relative documentation path, and Oxiquill adds `base`:

```js
export default defineOxiquillConfig({
  base: '/docs/',
  docRedirects: {
    '/guides/setup/': '/guides/getting-started/',
    '/ja/old-guide/': { status: 301, destination: '/ja/guide/' }
  },
  framework: { starlight }
});
```

Here `/docs/guides/setup/` redirects to `/docs/guides/getting-started/`. A destination must start with a single `/` and cannot contain route parameters. The build fails when a destination produces no page, for example after a typo or when `missingTranslations: 'omit'` leaves the target untranslated. Keep external and other non-documentation destinations in Astro's `redirects`; a source cannot appear in both.

## Japanese Typography

`oxiquill/styles/japanese.css` styles pages whose language is Japanese (`lang="ja"` or a `ja-` tag). It applies strict line breaking, so small kana and prolonged sound marks do not start a line, and sets line height and letter spacing for prose and headings. Pages in other languages are unaffected. Add it to `starlight.customCss`:

```js
starlight: {
  customCss: ['oxiquill/styles/japanese.css', './styles/custom.css'];
}
```

To tune the preset, set these properties on `:root` in a stylesheet listed after it:

| Property                         | Default  | Applies to                                                                 |
| -------------------------------- | -------- | -------------------------------------------------------------------------- |
| `--oq-ja-line-height`            | `1.9`    | Paragraphs, list items, definitions, quotations, table cells, and captions |
| `--oq-ja-letter-spacing`         | `normal` | The same prose elements                                                    |
| `--oq-ja-heading-line-height`    | `1.4`    | The page title and headings                                                |
| `--oq-ja-heading-letter-spacing` | `0.01em` | The page title and headings                                                |
| `--oq-ja-word-break`             | `normal` | Content; `auto-phrase` breaks at phrase boundaries in supporting browsers  |

## Path Fields

| Field                  | Default                        | Resolution base             |
| ---------------------- | ------------------------------ | --------------------------- |
| `workspaceRoot`        | project root                   | current project/config root |
| `frameworkRoot`        | installed `oxiquill` package   | absolute/package location   |
| `docsDir`              | `content/docs`                 | `workspaceRoot`             |
| `cratesDir`            | `crates`                       | `workspaceRoot`             |
| `publicDir`            | `public`                       | `workspaceRoot`             |
| `cacheDir`             | `.oxiquill`                    | `workspaceRoot`             |
| `downloadCacheDir`     | `.cache/oxiquill/downloads/v1` | `workspaceRoot`             |
| `generatedDir`         | `generated`                    | `cacheDir`                  |
| `rustCellsDir`         | `rust-cells`                   | `cacheDir`                  |
| `haskellCellsDir`      | `haskell-cells`                | `cacheDir`                  |
| `publicAssetsDir`      | `oxiquill`                     | `publicDir`                 |
| `rustWasmPublicDir`    | `rust-wasm`                    | `publicAssetsDir`           |
| `haskellWasmPublicDir` | `haskell-wasm`                 | `publicAssetsDir`           |
| `pyodidePublicDir`     | `pyodide`                      | `publicAssetsDir`           |
| `licensesPublicDir`    | `licenses`                     | `publicAssetsDir`           |

Every path accepts a relative string, an absolute string, or a `file:` URL. Nested relative paths resolve against the parent shown in the table, not against the process's incidental working directory.

Astro's `root`, `publicDir`, `outDir`, and `cacheDir` and Oxiquill's explicit path settings must normalize to the same locations when they describe the same directory. Conflicting explicit values are errors; Oxiquill never silently chooses one. All CLI commands load this resolved configuration before reading, writing, or cleaning files.

## Generated Rust Assets

Runnable manifests in `.oxiquill/generated/cells.json` include a version 1 `rust` registry. Each Rust cell belongs to exactly one module; generation currently produces a single module named `site`.

Each module records its build fingerprint, JavaScript glue URL, Wasm URL, Wasm SHA-384 integrity, byte length, and cell IDs. Files under `public/oxiquill/rust-wasm/` use names such as `site-<hash>.js` and `site-<hash>.wasm`. Their content-addressed URLs are immutable. The registry stores paths relative to `publicDir`; Astro resolves browser URLs under its configured `base`, including custom runtime directories.

The Rust worker loads a module when one of its cells first runs and verifies Wasm integrity while fetching it. Text-only and Python-only pages fetch no Rust module assets. Development updates invalidate changed module fingerprints; cancellation and timeout still reset the whole Rust worker. Generation publishes the new registry before removing obsolete registered module assets.

Source-only `docgen` does not compile Rust. Run `oxiquill docgen --wasm dev` or build the site to produce runnable module assets. Do not edit generated manifests or assets manually.

## Python Downloads

```js
export default defineOxiquillConfig({
  python: {
    preload: false,
    offline: process.env.OXIQUILL_OFFLINE === '1',
    packageMirror: new URL('https://packages.example/pyodide/')
  },
  paths: {
    downloadCacheDir: new URL('./.cache/verified-downloads/', import.meta.url)
  }
});
```

`python.offline` defaults to `false`. `python.packageMirror` accepts a string or URL and changes the package download base without changing lockfile integrity checks. `paths.downloadCacheDir` also accepts a string or URL. The exported `OxiquillPythonOptions` and `OxiquillPathOptions` types describe these public fields.

## Precedence and Merging

1. `--config <path>` selects the config file; otherwise Astro's normal config discovery applies.
2. Explicit project settings override defaults.
3. `starlight.title`, `starlight.description`, and `starlight.sidebar` override the shorthand fields.
4. Consumer Markdown, Vite, CSS, component, and integration additions are retained after Oxiquill's required entries.
5. A conflicting path, missing Oxiquill integration, multiple Oxiquill integrations, or an unreadable config fails before generation or cleanup.

## Cleanup Ownership and Safety

`oxiquill clean` recursively removes exactly three resolved roots: `cacheDir`, Astro's `outDir`, and `publicAssetsDir`. It does not remove `downloadCacheDir`; the default verified download cache at `.cache/oxiquill/downloads/v1` persists across clean and can be reused by later generation.

The exact default roots `.oxiquill`, `dist`, and `public/oxiquill` are reserved generated locations and may be cleaned without an ownership marker. For a custom cleanup root, the corresponding generation or build lifecycle writes `.oxiquill-ownership.json` after claiming a missing or empty directory. A pre-existing non-empty custom directory without the matching marker is never inferred to be generated output. Do not create or edit the marker manually.

Every recursively deleted root must stay inside `workspaceRoot`. Cleanup roots must be disjoint from one another and from `docsDir`, `cratesDir`, `publicDir`, `frameworkRoot`, the selected Astro config, recognized project config/manifest/lock files, the persistent download cache, and discovered VCS or package-installation state such as `.git` and `node_modules`. Generated child roles must also be disjoint from their siblings. The only authored/generated containment exception is a strict `publicAssetsDir` child below `publicDir`; it cannot equal `publicDir` or sit below another authored public subtree.

Oxiquill canonicalizes existing paths and symlinked ancestors before comparing or deleting them. Clean validates every root and every ownership marker before its first recursive deletion. If one root is unsafe or unowned, no root is removed; the diagnostic names the field, absolute resolved path, conflicting path role, and corrective action.

## Runtime Fingerprints

Runtime fingerprints contain semantic build inputs rather than machine-local paths. Python fingerprints include the Pyodide version, lockfile SHA-256, verified core-file hashes, selected package metadata, and requested package set. Haskell build fingerprints include the cells, generated source, supported compiler-version prefix, and the compiler's exact reported version (or its unavailable state). The Haskell compiler command, executable path, and diagnostic text are excluded, so moving an equivalent toolchain does not force a rebuild; changing its reported version or supported-version policy does.

Rust and Haskell build fingerprints also include the installed generator's content hash and package identity. This detects codegen, build-flag, postprocessing, staging, and runtime-data changes even when a workspace package version stays unchanged. Rust additionally hashes `RUSTFLAGS`, `CARGO_ENCODED_RUSTFLAGS`, every `CARGO_PROFILE_*`, `CARGO_BUILD_*`, and `CARGO_TARGET_*` variable, and the workspace's `.cargo/config` and `.cargo/config.toml`. Unrelated environment variables are excluded. Artifact mode is recorded: production output may satisfy a dev request, while dev output must rebuild for production.

Before reusing published Rust, Haskell, or Python files, Oxiquill checks their recorded byte sizes and SHA-256 digests. Missing, edited, or truncated files trigger regeneration. Older runtime state without integrity records is regenerated automatically.

## Compiler Caches

Compiler caches live below the configured `cacheDir`: `build-cache/rust-target` for Cargo and `build-cache/haskell/<mode>-<ghc-version>` for Haskell. They survive runtime staging and failed compilation. Haskell uses stable cached source paths and preserves unchanged source timestamps so GHC can reuse module objects; mode and exact compiler version select separate caches. Cargo manages dependency recompilation itself.

Release Rust builds also cache `wasm-opt -O` results in `build-cache/wasm-opt` when an executable `wasm-opt` is on `PATH`. The cache keys the input bytes and size, optimizer version and executable hash, optimization arguments, schema version, and sorted `BINARYEN_*` environment variables. Installing, removing, or changing the optimizer invalidates Rust build reuse. Dev builds skip optimization; without a `PATH` optimizer, wasm-pack keeps managing Binaryen without result caching. Hits verify content integrity and copy bytes into the build stage. Corrupt entries regenerate automatically. The cache retains the 16 most recently used results and normally survives failed builds. `oxiquill clean` or `pnpm build:clean` clears it while preserving verified downloads.

Oxiquill passes the Cargo target directory to both `wasm-pack build` and `wasm-pack test`. An explicit `CARGO_TARGET_DIR` takes precedence and remains user-owned; clean does not delete an external target directory. Compiler caches are separate from published output and the verified download cache. `oxiquill clean` removes Oxiquill-owned compiler caches but preserves verified downloads.

Cargo configuration outside the workspace root, including ancestor `.cargo` files, `$CARGO_HOME/config*`, and files referenced by configuration, is not fingerprinted. After changing these inputs, run the repository's `pnpm build:clean`, or `oxiquill clean` followed by `oxiquill build` in a consumer project.

## Base Paths and Public Assets

Set Astro's `base` when publishing below a subpath. Oxiquill applies it to interactive-cell manifests, language runtimes, diagrams, and `/media/...` references. Keep every authored public URL in root-relative `/media/...` form, even when `base` itself is `/media` or starts the same way. Do not add the configured base manually; the normal Markdown pass prefixes the authored URL. Redirects to documentation pages use [`docRedirects`](#document-redirects), which also adds the base.

Generated runtime files belong under `.oxiquill` and `public/oxiquill`; the verified download cache belongs under `.cache/oxiquill/downloads/v1`; and the final static site belongs under Astro's `outDir` (normally `dist`). Generated directories and their ownership markers must not be edited directly. The download cache may be retained across builds and reconstructed outputs, but its files are verified before every use.

When you customize generated directories, update `tsconfig.json` exclusions to the resolved cache, helper-crate target, output, and public-asset paths. Otherwise a broad include such as `**/*` can make Astro/TypeScript analyze generated JavaScript such as Pyodide instead of treating it as output.

`python.preload` defaults to `false`. Enable it to prepare Python at DOM readiness on pages containing Python cells. See [Python Runtime Assets](/guides/python-runtime/#browser-preparation).

`python.additionalPackages` accepts package names mapped to `{ version, license, licenseFiles }` records. It extends the built-in allowlist using the installed Pyodide lock. Only packages required by cells are distributed. See [Additional Packages](/guides/python-runtime/#additional-packages) for dependency notices, integrity checks, and an example.

`python.experimentalSetup` defaults to `false`. Enable it to allow page-local Python setup references that execute afresh before each cell. See [Experimental Setup](/guides/python-runtime/#experimental-setup).

## Rust Compilation Groups

Set `rust: { grouping: 'page' }` in `defineOxiquillConfig()` or `oxiquillIntegration()` to compile each page's Rust cells into a separate module. Allowed values are `'site'` (the default, one module) and `'page'`. Pages without Rust cells create no Rust module.

```js
export default defineOxiquillConfig({
  framework: { starlight },
  title: 'My Docs',
  rust: { grouping: 'page' }
});
```

Page grouping rebuilds only modules whose source, helper dependency closure, toolchain, or build options changed. Readers download only the modules needed by cells they run. Shared dependencies are compiled once in the generated Cargo workspace but appear in each module that needs them, so total download/storage bytes can increase. Small sites often benefit from the default single module; page grouping bounds individual rebuild and page-download costs as a site grows. Use `oxiquill build --explain` to inspect the plan.

Page mode uses Cargo directly and requires a wasm-bindgen CLI version exactly matching the generated Cargo.lock. Oxiquill uses a matching binary on PATH or downloads the official host release, verifies its pinned SHA-256, and caches it under `paths.downloadCacheDir`. A mismatching PATH binary is replaced by the verified cached/downloaded choice for this build. Release optimization similarly uses wasm-opt from PATH or a verified Binaryen 117 release, retaining the existing `-O` optimization. Archive extraction requires `tar`. Failed verification or an unsupported host reports the expected tool version and cache path; installing the matching tool on PATH is an alternative.

Generated page crates have stable source paths below `paths.rustCellsDir`; compiler and optimizer caches stay shared. The runtime registry is published only after every required group succeeds. Failure retains the previous complete registry. Moving or deleting pages prunes obsolete owned modules after publication. `oxiquill clean` removes generated/compiler outputs while retaining verified tool downloads.
